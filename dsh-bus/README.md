# dsh-bus

在本机的多个 DSH 会话之间传话。不是「群聊」，是**一个会话对另一个会话说一句话**，说完各自继续干活。

用它的理由只有一个：你有两条（或更多）长期在跑的会话，但它们互相看不见。比如一个盯交易、一个做月频研究、一个是你直接对话的主会话——它们明明在同一个项目里，却只能靠那个「人」在中间转述。

## 它解决什么

- **实时插话**：`chat` 通道会把消息**推进**空闲会话并叫醒它（不是等它下次想起来读）。
- **不打扰的交接**：`digest` 通道只落队列，对方下次自己读，适合周报、月报、交接单。
- **花销有上限**：`chat` 每发一条，按该会话真实的 token 消耗折算成钱，扣当天的额度；额度用完只拦总线工具，不影响干活。
- **看得见回执**：`bus_peers` 告诉你「我发给他 3 条，他读了 2 条」——不用猜对方到底看没看。

## 安装

```bash
# 从这个目录装（本地 link，改代码后需要卸载重装才生效）
dsh plugin install /path/to/dsh-bus
```

装好后会自动多出五个工具，不需要重启电脑，但**宿主插件改动后要重启一次 Harness**。

## 五个工具

| 工具 | 干什么 |
| --- | --- |
| `bus_send` | 发一条给某个会话（或 `"*"` 广播） |
| `bus_wait` | 等对方的消息，收到立刻返回；`digest` 通道不等待，只取队列 |
| `bus_read` | 取走未读（取走即标记已读） |
| `bus_peers` | 看有哪些会话、最后活动、我发给它多少条、它还没读多少条 |
| `bus_budget` | 看今天花了多少、额度从哪来、记账解析到了哪个会话 |

## 用法

```
bus_send(me:"研究线", to:"交易线", text:"M3 那版参数我改了，今晚别按旧的跑", channel:"chat")
bus_wait(me:"交易线", timeoutSec:60)
bus_send(me:"交易线", to:"研究线", text:"收到，今晚用新参数", channel:"chat")
```

周报、交接、长文档摘要走 `digest`：

```
bus_send(me:"交易线", to:"研究线", text:"本周复盘：……", channel:"digest")
```

## 两条通道的区别

| | chat | digest |
| --- | --- | --- |
| 是否叫醒对方 | 是（对方空闲时立刻被叫起） | 否，只落队列 |
| 是否计费 | 按真实 token 消耗计 | 不计费，只限条数 |
| 典型用途 | 白天讨论、临时插话、需要对方马上知道 | 周报/月报/交接/长摘要 |

## 额度怎么算

`chat` 的额度不是「按条数」，是**按钱**：每发一条，插件读你这次会话里 `assistant/message` 事件携带的 `usage`，用内置价格表折算成人民币，累加到当天的账上。价格表存在 `~/.dsh-bus/prices.json`，第一次运行自动生成，可以自己改。

- 默认每人每天 **¥2**，可通过 `bus.json` 或环境变量 `DSH_BUS_DAILY_YUAN` 调整。
- 记账口径默认只看**当前这一轮**（`scope: "turn"`）；设成 `"session"` 则统计「自上次调用总线以来的全部消耗」。
- `digest` 不扣钱，只限条数（默认 30 条/天）。

## 已读回执

`bus_peers` 里每个会话有两列：`received`（我发给它多少条）、`unreadByThem`（其中它还没读多少条）。读到就记一条回执，发送方查得到——但**它读≠它回**，回不回是对方的选择。

## 多场景：它在什么条件下能用

这套东西的边界不在功能多少，而在**运行环境**。装之前先对一下：

| 场景 | 能不能用 | 说明 |
| --- | --- | --- |
| 同一个 DSH 进程里的多个会话 | 全部可用 | 唤醒、已读、额度都正常 |
| 不同进程（桌面端 + CLI）之间 | 收发可用，**唤醒不可用** | 唤醒走的是进程内的 agent 引用，跨进程看不见对方；`bus_send` 会返回「对方没上线过总线」，消息仍会落库，对方下次 `bus_read` 能读到 |
| 不同工作区（不同项目目录） | 可用 | 数据库在用户目录，不跟工作区绑定 |
| 只读盘 / 沙箱拦写入 / 权限不足 | 自动降级 | 写不进 `~/.dsh-bus` 时自动落到系统临时目录，`bus_peers` 会显示实际数据目录；临时目录可能被系统清理，属于降级不是常态 |
| 文件策略是 `workspace-write`（默认） | 可用（已实测） | 插件跑在宿主进程里，直接调 `fs`，不受工具沙箱约束；实测在 workspace-write 下依然能读写 `~/.dsh-bus`。**但**：这时宿主工具（pwsh / read / write）反而打不开这个库，人工排查得靠 `bus_peers` 输出的数据目录，或临时把策略放开 |
| 多台机器 | 不可用 | 没有网络层，这是刻意的（见「设计取舍」） |

`bus_peers` 第一行会打印**实际数据目录**，出问题时先看这一行——它告诉你数据到底落在哪、是不是降级了。

## 配置

优先级：**环境变量 > `~/.dsh-bus/bus.json` > 内置默认**。

```json
{
  "chatDailyYuan": 2,
  "maxBody": 2000,
  "digestMaxSent": 30,
  "chatMaxSent": 200,
  "defaultWait": 60,
  "wakeMaxPerDay": 30,
  "wakeMinGapMs": 8000,
  "retentionDays": 30,
  "scope": "turn"
}
```

数据默认放在 `~/.dsh-bus/`（`bus.db` 是 SQLite，`prices.json` 是单价表）。可用 `DSH_BUS_DIR` 换目录。

## 常见的坑

1. **对方读了却没回你。** 总线只负责投递，不负责对方回话。叫醒的消息里会附一行「回信请用 bus_send」，但不保证对方照做——`bus_peers` 的 `unreadByThem` 能帮你确认它到底看没看。
2. **名字拼错=发给了另一个人。** `me` 和 `to` 都是字符串，没有身份校验；第一次用就固定下来，改名会断掉未读游标。
3. **对方从没调用过总线。** 没有 `agent_id` 就无法唤醒，`bus_send` 会返回「对方没上线过总线」。让它先跑一次 `bus_peers` 完成注册。
4. **广播 `"*"` 不唤醒任何人**，只投递。
5. **唤醒有上限**：每对象每天 30 次、间隔 8 秒，防止两个会话互相刷屏烧钱。

## 安全

- 不要用总线传凭据、授权码、密码。它落的是明文 SQLite。
- 消息默认保留 30 天（`retentionDays`），到期自动清。
- 插件不做网络请求，只读写本机一个 SQLite 文件。

## 设计取舍

- **不做群聊。** 多对多的房间会让每个会话都读一堆跟自己无关的话，直接烧钱；一对一才符合「有事说事」。
- **按钱不按条。** 一条 3000 字的长文和一句「收到」不是一个成本，按条限制会逼出「一次塞满」的反向操作。
- **唤醒不是必达。** 对方可能在跑长任务、可能没注册、可能被限流；发送方能看到原因，但不会因此阻塞。
